## escalation_marker honoring (2026-06-10 TEMP-flip revert)

Seven 2026-05 `TEMP` critical→warning flips (plus one deferred revert) in `config/workflows.yaml::textbook_to_course` were introduced because the Block-input inter-tier / post-rewrite validators audited **every** Block in the input list — including blocks the router had already terminally escalated (`Block.escalation_marker` non-null: outline budget exhausted, validator consensus failure, structural-unfixable, dispatch error, per-claim attribution unfixable). On a corpus that legitimately escalated some fraction of its blocks, these gates fired `action=block` against the degenerate content the escalation already recorded — a guaranteed false positive for the blocks that never ship. The flips' recorded revert condition was "once the validators honor `block.escalation_marker`".

The hook is now in place, but it honors the marker the way the **packager** does — NOT a blanket marker skip. `Courseforge/router/inter_tier_gates.py::_is_unshipped_escalation_tombstone(block)` and `lib/validators/rewrite_html_shape.py::_is_unshipped_escalation_tombstone(block)` skip a Block **only when** `escalation_marker is not None AND not (content or "").strip()` — i.e. a marker + empty *tombstone* that the packager filters out of the IMSCC (the exact ship-exclusion predicate at `MCP/tools/pipeline_tools.py`'s per-page emit filter, `pipeline_tools.py:5226`). A marker + non-empty *salvaged* block (escalated-rewrite salvage path, `Courseforge/generators/_rewrite_provider.py::_apply_rewrite_touch` via `dataclasses.replace`, marker preserved) DOES ship — per the design comment at `pipeline_tools.py:5135` — and stays on the audit path. Every `Block*Validator` (`BlockCurieAnchoringValidator`, `BlockContentTypeValidator`, `BlockPageObjectivesValidator`, `BlockSourceRefValidator`) plus `RewriteHtmlShapeValidator` honors it; tombstones are skipped (no audit, not counted toward `audited`, no issue emitted), salvaged-with-content blocks are audited.

The IMSCC-side backstop is `lib/validators/imscc.py::IMSCCValidator._check_escalated_blocks_absent` (code `ESCALATED_BLOCK_IN_IMSCC`), which confirms no tombstone leaked into shipped HTML. It is wired at **warning** severity in `textbook_to_course` and is **input-starved** in fully orchestrated runs (it no-ops unless `blocks_final_path` + the shipped HTML are threaded into its inputs), so it is NOT a critical leak backstop — the lockstep tombstone-skip predicate above is what keeps salvaged-with-content blocks on the audit path. With the false-positive class (tombstones only) removed from the gates, the flips were reverted to `critical` (`on_fail: block`) on 2026-06-10:

| Gate | Phase | Disposition |
|------|-------|-------------|
| `outline_curie_anchoring` | `inter_tier_validation` | reverted → critical |
| `outline_content_type` | `inter_tier_validation` | reverted → critical |
| `outline_page_objectives` | `inter_tier_validation` | reverted → critical |

## IB6 landing (eight-dimension quality-rubric scoring capstone)

IB6 stands up the framework's **scored, not asserted** model: every block is
scored on the eight orthogonal 0-3 dimensions (Alignment, Cognitive-load fit,
Multimedia integrity, Retrieval/spacing, Feedback, Engagement, Accessibility/
UDL, Coherence) by COMPOSING already-computed validator signals (no new scoring
engine, no second NLI/embedding model load), then rolled up block→module→course
with BOTH a mean path AND a per-dimension minimum-floor path so no weak block
hides in a strong average.

Five new block-quality gates wire **warning day-1** at BOTH
`inter_tier_validation` and `post_rewrite_validation` in `course_generation` +
`textbook_to_course` (+10 warning each workflow): `block_cognitive_load`
(IB6.4), `anatomy_slot_presence` (IB6.2), `interaction_feedback` (IB6.3),
`block_quality_rubric` (IB6.1 keystone), `qa_checklist` (IB6.7). Each gate's
validator no-ops (`passed=True` + an info issue) when the keystone flag
`ED4ALL_BLOCK_QUALITY_RUBRIC` is unset, so default-off runs are byte-stable even
with the gates wired. The IB6.5 `(verb · level · knowledge-type)` chip + B01
both-axes (`OBJECTIVE_KNOWLEDGE_TYPE_MISSING`) assertion ride on the existing
`abcd_verb_alignment` gate at `course_planning` (no new gate). Three further
additive checks ride the SAME gate (no new gate; each default-OFF byte-stable):
W1.1 `OBJECTIVE_VAGUE_VERB` (warning; `ED4ALL_OBJECTIVE_OBSERVABLE_VERB` — flags a
non-observable main verb on the objective statement's legacy no-ABCD path),
W1.4 `ABCD_BLOOM_LEVEL_INFERRED` (info; `ED4ALL_OBJECTIVE_INFER_BLOOM` — infers a
null `bloom_level` from `behavior.verb` instead of skipping the verb-Bloom audit),
and W1.3 `ABCD_INCOMPLETE` (warning; gated by the existing `require_abcd` input,
no new flag). The `chunkset_manifest` gate similarly gains two additive
default-OFF import-coverage codes: `CHUNKSET_COVERAGE_LOW`
(`ED4ALL_CHUNK_COVERAGE_FLOOR`) and `CHUNKSET_TOO_THIN` (`ED4ALL_MIN_CHUNKS`).

Three hard gates override the mean: (1) Accessibility==0 fails the block
outright + fails the course (applied at rollup, `BlockQualityRollupAggregator`);
(2) assessment Bloom < objective Bloom caps Alignment at 1 (reuses IB3
`alignment_cap_at_1`, applied in IB6.1 scoring); (3) interaction-without-feedback
caps Feedback + Coherence at 1 (reuses the IB6.2/IB6.3 `caps_dims_by_block`
directive). Module passes only when `module_mean ≥ 2.0 AND every required-dim
minimum ≥ 2.0`; course needs zero a11y-gate failures + 100% alignment coverage.

block early runs. Count moves (re-derived from `config/workflows.yaml`):
`course_generation` 15→25 warning, `textbook_to_course` 59→69 warning.

## W2.1 validator CUDA-OOM error-handling (no new gate)

`ED4ALL_VALIDATOR_FAIL_CLOSED_ON_OOM` (default OFF) rides the EXISTING gate
error-handling path in `MCP/hardening/validation_gates.py::ValidationGateManager`
— it registers NO new gate row and changes NO Active-Gates count. When a
validation gate raises a CUDA out-of-memory error (NLI / embedding validators
contending for the shared 8GB card), `lib/llm/oom.py::is_cuda_oom` detects it and
`_build_oom_gate_result` emits a DISTINCT, greppable warning-severity
`VALIDATOR_OOM` `GateIssue` plus a `validation_result` DecisionCapture instead of
the pre-fix SILENT auto-pass under `behavior_on_error=warn`. Default OFF still
honours the gate's declared `behavior_on_error` for pass/block (the OOM is merely
made visible); truthy (`1`/`true`/`yes`/`on`) fails the gate CLOSED (critical,
blocks) regardless of `behavior_on_error`. Parse-with-fallback (garbage → off).
No workflow gate-count change.
