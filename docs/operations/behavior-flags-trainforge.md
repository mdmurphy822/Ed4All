# Trainforge behavior flags

Canonical per-flag reference for the `TRAINFORGE_*` / `LOCAL_SYNTHESIS_*` / `TOGETHER_*` / `ANTHROPIC_SYNTHESIS_*` / `CURRICULUM_ALIGNMENT_*` / `WAVE18_*` / `NVIDIA_*` env-var prefixes.
Split out of `Trainforge/CLAUDE.md` so the table is not loaded into context
on every session that touches `Trainforge/`. Grep it by flag name:

```bash
grep -n '<FLAG_NAME>' docs/operations/behavior-flags-trainforge.md
```

Ownership and the per-prefix index live in the root `CLAUDE.md`
§ Opt-In Behavior Flags.

---

Trainforge-owned env-var toggles (default off unless noted). All gate opt-in strict / stable-ID / provenance / experimental behavior; backward-compatible by default. Long-form rationale also lives in `schemas/ONTOLOGY.md` § 12.

**Count: 77** flags across `TRAINFORGE_*` / `LOCAL_SYNTHESIS_*` / `TOGETHER_*` / `ANTHROPIC_SYNTHESIS_*` / `CURRICULUM_ALIGNMENT_*` / `WAVE18_*`, plus the **3** vendor `NVIDIA_*` rows (`NVIDIA_API_KEY` / `NVIDIA_BASE_URL` / `NVIDIA_LARGE_MODEL`) — one row per flag, matching the per-prefix figures in the root `CLAUDE.md` index. Two `ED4ALL_*` rows below (`ED4ALL_ASSESSMENT_PROSE_PROVIDER`, `ED4ALL_ASSESSMENT_DIVERSIFIED`) are documented here rather than in the root table because Trainforge owns their behavior; they are excluded from BOTH tallies — this doc's count above and the root cross-cutting table's row count — per the subsystem-owned `ED4ALL_*` note at the end of `docs/operations/behavior-flags.md`.

Not flags, and deliberately absent from the table: `TRAINFORGE_SYNTHESIS_RUN_CONTRACT_SHA256` and `TRAINFORGE_SYNTHESIS_CONTRACT_COMPONENTS_SHA256` are **written** into the environment by `run_synthesis` so downstream steps can read the generation-contract fingerprint. Setting either by hand does not configure anything.

Governs `BloomBertEnsemble._load_members`'s two degradation arms. CURRENT live behavior: per-member dispatch (`_classify_with_member`) is an unfinished Subtask-25 placeholder, so the production loader degrades HONESTLY rather than fabricating votes — (1) when `transformers` is absent, default mode returns an empty member list (`classify()` yields the `winner_level="unknown"` sentinel → `_classify_bloom` returns `(None, None)` → the promotion `low_bloom_alignment` criterion skips); (2) when `transformers` IS present but per-member dispatch is unimplemented, default mode ALSO degrades to `unknown`, logging a one-time process-level warning (latched via `_UNIMPLEMENTED_DISPATCH_WARNED`). When truthy (`true`/`1`/`yes`/`on`), BOTH arms instead raise `BertEnsembleDepsMissing` — strict mode refuses to be silently handed an always-unknown classifier. This avoids the latent bug where loading the three SHA-pinned models and discarding their `("remember", 0.5)` placeholder outputs fabricated a unanimous-`remember` vote that collapsed training synthesis to zero non-remember pairs. Does NOT select an LLM provider/model — it only gates model-loading strictness. Default off → honest degradation. |

Default off → page-level key concepts copied onto every chunk (byte-identical legacy behaviour). |
| `TRAINFORGE_PAGE_CONCEPT_FALLBACK` | When on, the `chunking`-phase chunk emitter (`MCP/tools/pipeline_tools.py`) derives a PAGE-LEVEL key-concept list for every parsed page whose parser-harvested `key_concepts` is empty (via `lib/ontology/page_concept_fallback.py::apply_page_concept_fallback`) and assigns it to `item["key_concepts"]` BEFORE the existing page-level `extract_concept_tags` path runs, so all chunks of the page share the same tag set — the vendor semantics. Deliberately PAGE-level, NOT chunk-local (chunk-local tags fragment the KG — this leaves `TRAINFORGE_CHUNK_LOCAL_TAGS` unset). Only fills EMPTY `key_concepts` — a page with real parser-harvested concepts is untouched, and a textless page keeps its empty value (never rewritten to `[]`). Best-effort: a derivation failure logs a warning and keeps the parser `key_concepts`. Default off → byte-identical legacy emit (item dicts unchanged). **Marketable-v1 A5: auto-on for `textbook_to_course` / `course_generation` runs** via `MCP/core/workflow_runner.py::_apply_corpus_generalization_defaults` (setdefault — an explicit value wins); bare library calls keep default-off. | `TRAINFORGE_CHUNK_OVERLAP_WORDS` | Positive-int verbatim chunk-overlap budget (Track K, corpus-grounded pipeline improvements). Default `0` (unset / non-positive / garbage → `0`, parse-with-fallback) → **no-op, byte-identical legacy emit** (no manifest `overlap_words` key, no chunk text change). When `> 0`, both chunk emitters (the `chunking` and `imscc_chunking` phase handlers in `MCP/tools/pipeline_tools.py`) run the deterministic `Trainforge.chunker.apply_chunk_overlap` post-pass over the FINAL emitted chunk list (after every drop/filter pass): it prepends the verbatim trailing N words of each chunk's prior EMITTED chunk onto the next chunk's `text` so boundary content that split across a chunk break is recoverable at retrieval time. **Anti-fabrication**: the prepended prefix is composed solely from the prior chunk's own words — never synthesized, read from a pre-mutation snapshot so the overlap never compounds. **Continuity guard**: a chunk carrying the canonical `follows_chunk` linkage bleeds only from the chunk it genuinely follows (`follows_chunk == prev.id`), so overlap never crosses a lesson/module boundary where `follows_chunk` resets to `None`; generic chunk dicts without the linkage fall back to pure sequential overlap. Mutated chunks recompute `word_count`/`tokens_estimate` to stay consistent. The budget is recorded as the OPTIONAL `overlap_words` field in the chunkset manifest (`schemas/library/chunkset_manifest.schema.json`) for replay, omitted when off. NO gate (deterministic chunker option). Resolver `Trainforge.chunker.resolve_chunk_overlap_words`. Selects no LLM provider/model → no `docs/LICENSING.md` row. Regression net: `Trainforge/chunker/tests/test_chunk_overlap.py`. |
| `TRAINFORGE_RELOCATE_STRANDED_HEADINGS` | When on, the `chunking`-phase chunk emitter (`MCP/tools/pipeline_tools.py`) runs the deterministic `Trainforge.chunker.relocate_stranded_heading_tails` post-pass over the FINAL emitted chunk list (after every drop/filter pass, before the Track-K overlap pass). Vendor-parity audit defect D4 fix for the SemantiK GLM-OCR lane: a chunk whose right-stripped `text` ends with a STANDALONE next-section heading marker — an `N.M` section number + a single trailing `EXERCISES` / ≥3-letter all-caps word, preceded by a newline OR sentence-terminal punctuation + whitespace, with nothing after it — has that marker MOVED to open the FOLLOWING chunk (prepended as `"<marker>\n"`), recovering the heading that OCR stranded on the prior section's tail (e.g. `"...Figure. 1.1 EXERCISES"` → `"...Figure."` + `"1.1 EXERCISES\n"` opening the next chunk). **Conservative**: fires only when a SAME-FLOW follower exists (`next.follows_chunk == cur.id` OR equal `source.module_id`), never empties a chunk, never fires mid-sentence (the `$`-anchor forbids any continuation), and de-dups when the next chunk already opens with the marker (tail stripped, no duplicate). Text-only mutation — `text` + recomputed `word_count`/`tokens_estimate` (`int(word_count*1.3)`, matching `_create_chunk`); `html` deliberately untouched (the `apply_chunk_overlap` precedent), as are `id`/`follows_chunk`/`source`. Idempotent (a second pass no-ops). Fail-soft: an exception logs a warning and keeps all chunks. | `TRAINFORGE_DROP_FRONTMATTER` | When on, the `chunking`-phase chunk emitter (`MCP/tools/pipeline_tools.py`) applies the front-matter / donor / marketing CONTENT classifier `Trainforge/chunker/frontmatter.py::partition_frontmatter` over the just-chunked list (after `chunk_content`, before dedup/emit) and DROPS chunks classified as front-matter contamination — the cover/title page, the contributing-author list, the copyright + ISBN + Creative-Commons attribution block, donor/foundation acknowledgements, the Table of Contents, and the "Key Features"/"Additional Resources" preface. A full-textbook PDF carries ~6-8 such chunks at its head that the curated baseline never ingested; left in, they get CITED by synthesized objectives and pollute grounding. The classifier is **multi-signal scored** (a chunk drops only on ≥2 distinct signature families, or ≥1 STRONG signature — copyright / donor / marketing / TOC — while still inside the first-`DEFAULT_COVER_REGION_CHUNKS` cover region) with a **hard math-content veto**: any chunk carrying real worked math (numbered `EXAMPLE N.N` markers, `TRY IT` lead-ins, spaced arithmetic / `÷×=` relations, circled-letter sub-questions ⓐⓑ, multi-line bracket glyphs) is NEVER dropped, no matter how many marketing signatures it also hits. The **"Chapter 1 Foundations" false-positive guard**: 68/72 chunks of the real algebra corpus contain "foundation" (the legitimate algebra chapter title), so the donor signal matches only the acknowledgement surface ("Foundation, Inc.", named-donor couplets gated by an acknowledgement-context cue + a section-title stoplist) and NEVER bare "foundation"/"Foundations". Measured on a real algebra-textbook chunkset: drops exactly 6 genuinely-contaminated chunks (cover/authors/copyright, donor+TOC+marketing, chapter-preview blurbs, Key Features, Answer-Key/Resources, chapter-1 outline splash), preserves all 64 "foundation" chunks, drops ZERO real-math chunks. Each drop emits a `frontmatter_chunk_drop` decision-capture event (`phase=textbook-ingestor`, `tool=trainforge`) whose rationale interpolates the matched signatures + chunk id (deterministic prune, still audit-captured per the contamination-control contract). Fail-soft: a classifier exception logs a warning and keeps all chunks. Default off → byte-identical legacy emit. **Marketable-v1 M1: auto-on for `textbook_to_course` / `course_generation` runs** via `MCP/core/workflow_runner.py::_apply_corpus_generalization_defaults` (setdefault — an explicit value wins); bare library calls / non-pipeline rebuilds keep default-off. A fifth, weaker net requires >= 25 distinct content tokens the prompt does not already carry, and the chosen/rejected token-Jaccard must sit in `[0.30, 0.70]` (HA-DPO minimal-difference discipline below, the schema's own `>= 0.3` delta above). Mining is SKIPPED (`reject_mining_skipped="incomplete_pass"`) when the generation pass stopped early or exhausted its dispatch budget, because a partial pool is a biased pool. Checkpoint identity classifies `TRAINFORGE_SYNTHESIS_MAX_CONCURRENT` and
`TRAINFORGE_EVAL_PROGRESS_EVERY` as behavior-neutral operational values, so
changing concurrency or reporting cadence never regenerates terminal work.
`ED4ALL_LLM_REQUEST_TIMEOUT_SECONDS` is likewise transport-only and outside
the runtime-policy allowlist. Model, endpoint, generation parameters, tracked
prompt/factory/schema/validator code, source/focus, and all synthesis/NLI/
embedding/Bloom policy inputs remain fingerprinted. Modern accepted and
rejected pair checkpoints both carry that contract fingerprint; legacy
accepted rows without one retain their established replay compatibility.
Historical rejected and generation rows whose opaque fingerprint was produced
from older tracked source bytes are never guessed, whitelisted, or rewritten
as current: they regenerate once under the current contract. Retriable attempt
lineage may therefore restart for those stale rows. Newly generated rows carry
the current fingerprint and remain stable when only concurrency changes
(including a deployment-specific concurrency change). Fingerprint-free legacy accepted rows are not migrated or
stamped; replay still requires the established provider, focus, and pair-shape
compatibility checks. An operator requiring proof against every newly added
validator must choose a full accepted-pair regeneration.

#### Two run-ending synthesis failures an operator will meet

Both are deliberate, loud, and terminal — neither is retried and neither
degrades silently.

- **`FreshStartError: synthesis generation contract changed mid-run (... ->
  ...); ... archive and restart from zero`** — raised by
  `Trainforge/synthesis_fresh_start.py` when `TRAINFORGE_SYNTHESIS_FRESH_START_ID`
  binds a verified fresh-start marker and a GENERATION-contract input changed
  after that marker was written. Resuming would blend rows produced by two
  different implementations into one corpus with no way to separate them again,
  so the guard deliberately does NOT rebind. The message names the components
  that moved. **Operator action:** archive the existing synthesis output +
  resume sidecars and restart synthesis from zero — do not hand-edit the marker.
  The generation contract is the 18-entry `_GENERATION_CONTRACT_FILES` tuple in
  `Trainforge/synthesize_training.py`.
- **`RuntimeError: duplicate generation terminal for semantic key ...; exactly
  one writer must close each unit`** — raised by
  `Trainforge/synthesis_journal.py` when a generation unit reaches a terminal
  disposition (`success` / `fatal`) twice. This is an invariant violation, not a
  cache hit: exactly one source-order writer closes each unit, so a second
  terminal means double dispatch, a resume that re-queued already-completed
  work, or two writers racing on the same journal. It is raised rather than
  logged on purpose — the second write is the only moment the corruption is
  visible. **Operator action:** confirm only one synthesis process owns the
  course directory, then restart; do not delete journal rows to get past it.

**The complementary fact that makes this coherent:** VERDICT-policy changes do
NOT re-key generation. The 17-entry `_VERDICT_POLICY_FILES` tuple (validators,
thresholds, NLI/Bloom classifiers, the embedder, the objective-delivery axes,
and `synthesis_reject_mining` — which DERIVES rows from already-generated text
and so cannot alter a model call) is
recorded on each row but excluded from the generation fingerprint, so editing a
validator re-evaluates verdicts without regenerating a single pair and a run
continues straight across it. Only a change to one of the 18 generation-contract
files hard-stops a bound run. Both tuples live in
`Trainforge/synthesize_training.py`.

### Recommended graph-shaping config (canonical rebuild)

The measured known-good flag set for a canonical corpus rebuild, split by pipeline stage:

```bash
# Chunking (PAGE-level tags — leave TRAINFORGE_CHUNK_LOCAL_TAGS UNSET)
export TRAINFORGE_PRUNE_SCAFFOLDING_CONCEPTS=true
export TRAINFORGE_SEED_TECH_CONCEPTS=true
export TRAINFORGE_FILTER_FRAGMENT_CONCEPTS=true
export TRAINFORGE_CHUNK_TYPE_CONTENT_AWARE=true

# Knowledge graph
export TRAINFORGE_MERGE_DUPLICATE_CONCEPTS=true
export TRAINFORGE_INTRA_CHUNK_LINKS=true
export TRAINFORGE_RELATED_FANOUT_CAP=8
export TRAINFORGE_NORMALIZE_LABELS=true
```

Measured rationale: the prune + tech-seed + fragment-filter + content-aware-typing chunking stage plus PAGE-level tags (chunk-local tags fragment the graph: per-chunk tag sets rarely overlap, so the co-occurrence pair-counting floor is never reached and the graph shatters into one-node components) yields a dense, clean tag distribution; on the canonical rebuild **204/204 `targets-concept` LO endpoints survive post-materialization**, the cap-8 `related-to` fan-out removes the spurious hub tail with **zero re-stranding** of peripheral-but-genuine concepts (union top-K semantics), and the typed pedagogical edges (`defined-by`/`exemplifies`/`is-a`/`prerequisite`) carry connectivity so the merge + intra-chunk-link passes never strand a single-section topic.

**Marketable-v1 A5 — auto-on for pipeline runs.** The `dedicated micro-wave` this paragraph anticipated has landed: `MCP/core/workflow_runner.py::run_workflow` now turns this measured-best set ON for every `textbook_to_course` / `course_generation` run (`_apply_corpus_generalization_defaults`, applied right after the workflow config resolves), so a fresh CLI or GUI run gets the features the product is sold on — page-level concept tags, the prune+fragfilter+merge+cap quartet, dynamic CURIEs, three-stage synthesis — without the operator setting any env var. The runner uses setdefault semantics (an explicitly-set env value, legacy or otherwise, is honored verbatim) and `RELATED_FANOUT_CAP` defaults to `8`. `TRAINFORGE_CHUNK_LOCAL_TAGS` is deliberately **left out** of the auto-on set (it stays default-off → page-level tags emit), because chunk-local tags fragment the graph. The byte-stability contract is preserved for everything OUTSIDE a pipeline run: a bare `lib.ontology` / `Trainforge.chunker` library call that never reaches `run_workflow`, and any rebuild that doesn't go through the runner, keeps the legacy default-off behavior, so legacy calibration-corpus archives are still byte-reproducible from a clean env. The `export …` block above is still the way to reproduce the config for an out-of-band rebuild that bypasses the runner.
