# Aggregators

> Long-form home for the per-aggregator detail. Root `CLAUDE.md § Aggregators` carries the 5-row summary table; this file carries the canonical paragraph-bullet for each aggregator. When adding a new aggregator, extend both surfaces.

Top-level workflow aggregators run post-loop in `WorkflowRunner.run_workflow` and roll up per-phase signals into a single operator-facing JSON. Best-effort: aggregator failure logs a warning but does not change `final_status` (per-phase reports remain authoritative). Live aggregators:

- `lib/aggregators/courseforge_validation_report.py::CourseforgeValidationReport` — walks every per-phase `report.json` (inter_tier_validation, post_rewrite_validation) plus in-memory `_gate_results` chains and writes `<project_path>/courseforge_validation_report.json` (schema 1.1). Carries `per_block_results[]`, `source_grounding_results`, `accessibility_results`, `statistical_semantic_results`, `manifest_hash_results`, plus the `final_promotion_decision` enum (`failed | non_certified_archive | certified_accessible | certified_instructional | certified_trainable`). Emits `courseforge_validation_aggregated` decision per build.
- `lib/aggregators/trainforge_assessment_quality_report.py::TrainforgeAssessmentQualityReport` — aggregates `training_synthesis` / `trainforge_assessment` / `libv2_archival` `_gate_results`, the `<trainforge_dir>/quality/quality_report.json::assessments` dimension, and (when an adapter is imported) `LibV2/courses/<slug>/models/<id>/eval/eval_report.json` into a single `<libv2_course>/quality/trainforge_assessment_quality_report.json` (schema 1.0). Falls back to `<trainforge_dir>/trainforge_assessment_quality_report.json` when archival hasn't run. Carries `summary` (total_questions, answerable_rate, single_correct_rate, bloom_alignment_rate, placeholder_rate, source_support_rate), `synthesis_quality`, `kg_quality`, `eval_summary`, `per_question_issues`, plus a 3-way `promotion_decision` enum (`failed | non_certified_archive | trainable`). Emits `trainforge_quality_aggregated` decision per build. Heuristic replaced by Wave 3 G1's master promotion-chain compose.
- `lib/aggregators/coverage_map.py::CoverageMapAggregator` — builds an objective-keyed coverage table linking objectives -> chunks -> questions -> training_pairs from `course_planning` synthesized objectives, `imscc_chunks/chunks.jsonl::learning_outcome_refs[]`, `assessments.json::questions[]` `objective_id` / `source_chunks[]`, and `training_specs/{instruction,preference}_pairs.jsonl::lo_refs[]`. Writes `<libv2_course>/coverage_map.json` (schema 1.0; canonical shape pinned at `schemas/aggregators/coverage_map.schema.json`). Falls back to `<trainforge_dir>/coverage_map.json` when archival hasn't run. Surfaces three orphan classes — `summary.orphan_objectives` (objective with no chunks AND no questions AND no training_pairs), `summary.orphan_chunks` (chunk with empty / non-extant `learning_outcome_refs[]`), `summary.orphan_questions` (question with empty / non-extant `objective_id` / `objective_ids[]`) — plus per-objective `answers_grounded_in_chunks[]` (questions whose `source_chunks[]` intersect the objective's collated chunk list). Emits `coverage_map_aggregated` decision per build.
- `lib/aggregators/promotion_chain_report.py::PromotionChainAggregator` — Wave 3 W3.G master governance aggregator. Walks all 9 arrows of the conversion -> eval-report chain (source PDF -> SemantiK accessible HTML -> CourseForge blocks -> rewritten HTML -> IMSCC -> IMSCC chunks -> assessment items -> training pairs -> adapter -> eval report; the source/HTML arrows carry the preserved `data-dart-*` provenance), reads each per-stage report best-effort, and writes a single canonical `<libv2_course>/courseforge_promotion_chain_report.json` (schema 1.0; canonical shape pinned at `schemas/governance/promotion_chain.schema.json`). Falls back to `<trainforge_dir>/courseforge_promotion_chain_report.json` when archival hasn't run. Per-arrow rows carry `{arrow_id, name, input_hash, output_hash, validator_set[], passed, warnings_count, source_coverage, promotion_decision}`. Top-level `chain_hash` is a deterministic SHA-256 over the canonicalised arrow rows in chain order; `course_status` references the Wave 1 G2 5-value enum (`failed | non_certified_archive | certified_accessible | certified_instructional | certified_trainable`) and is composed by `lib/governance/course_status.py::derive_course_status`. **Anti-silent-degradation contract**: when a per-stage report is missing the aggregator MUST emit `promotion_decision: "fail"` on that arrow with `validator_set: ["missing_stage_report"]` and surface `course_status: "failed"`. Emits `promotion_chain_aggregated` decision per build. Supersedes the per-aggregator `final_promotion_decision` heuristics in W2.A (`courseforge_validation_report.json`) and W2.B (`trainforge_assessment_quality_report.json`).
- `lib/aggregators/edge_consensus.py::EdgeConsensusAggregator` — GPT-feedback (12 May 2026) item 2, **v2 cross-stratum triangulation redesign** (`MATRIX_VERSION = "2026-06-09.v2"`). Walks `concept_graph_semantic.json`, stamps every edge with `edge_status` + `consensus_signals[]`, and writes the sibling `edge_consensus_report.json`. Also runs at the `concept_extraction` phase boundary (`apply_to_graph` in `MCP/tools/pipeline_tools.py::_run_concept_extraction`) so the LibV2-archived graph carries the verdicts.

  **Graded status tiers** (strongest verdict wins): `contradicted` > `retracted` (NLI, `TRAINFORGE_EDGE_NLI`) > `confirmed` > `supported` > `pending`. `consensus_rate = confirmed / total`; `supported_rate = supported / total` is reported **separately** so the soft tier never inflates the headline consensus number.

  **Why same-pair consensus was near-degenerate.** The v1 design asked "did a DIFFERENT rule fire over the same `(source, target)` pair?". `typed_edge_inference._apply_precedence` collapses colliding-pair edges upstream (`is-a` > tier-2 > `related-to`), deleting the same-pair co-fire evidence — so on a real general-textbook corpus graph 1891/1892 edges stayed `pending`. The recoverable signal is cross-stratum triangulation over the *persisted provenance endpoints*, which survive precedence because they live on edges of different (non-colliding) types.

  **Triangulation detectors** (`_compute_triangulation_signals`, fixed order, deterministic `sorted()` iteration):
  - **T1** `prerequisite_from_lo_order` × first-mention text order. Edge `B→A` means `A` (target) is the prerequisite of `B`; the prerequisite should appear *first* in the text. `first_mention_ord(A) < first_mention_ord(B)` → `agree` (`text_order_corroborates_lo_order`) → `confirmed`; `>` → `disagree` (`lo_order_vs_text_order_conflict`) → `contradicted`; tie / unparseable chunk-ordinal → no signal (`pending`, graceful degrade). The conflict detail string is deliberately distinct from the hard-cycle `circular_prerequisite` / `type_hierarchy_cycle` so operators can tell soft ordering conflicts from cycles.
  - **T2** `assesses_from_question_lo` (question→LO) × `derived_from_lo_ref` (chunk→LO) closing a `(chunk, LO)` triangle (`chunk_lo_triangle`), case-insensitive LO match; symmetric stamp on the derived edge via `assessed_chunk_lo`.
  - **T3** `targets_concept_from_lo` (LO→C) × `derived_from_lo_ref` (chunk→LO) × `defined_by_from_first_mention` (C→chunk) closing an LO–chunk–concept triangle (`lo_chunk_concept_triangle`); symmetric on the derived edge.
  - **T4** `related_from_cooccurrence` co-location: two co-occurring concepts whose first-mention chunks overlap → `support` (`co_located_first_mention`) → `supported`. `intra_chunk_link` is explicitly **excluded** (its edges *are* co-location edges, so a co-location signal over them is tautological — its matrix confirm set is empty by contract).

  **`evidence_diversity` block**: `multi_rule_pair_count` (node-pairs where >1 distinct rule fired), `multi_rule_pair_rate`, `triangulated_edge_count` (edges carrying ≥1 signal). T1 text-order conflicts flow into the existing `contradictions[]` list. Emits one `edge_consensus_resolution` decision per build (rationale interpolates the full count vector incl. `supported`). Attenuates `kg_quality.consistency` by `(1 - contradiction_rate)` inside `KGQualityValidator.validate`. Measured on a real general-textbook corpus graph (1892 edges): 303 confirmed / 750 supported / 59 contradicted / 780 pending, `contradiction_rate ≈ 0.031`, all 59 contradictions the soft `lo_order_vs_text_order_conflict` class.

  **NLI text-entailment extension** (`TRAINFORGE_EDGE_NLI`, opt-in, default off → the aggregator runs the cross-rule-matrix + triangulation consensus only). Now **implemented** (`_nli_extension_signal`), superseding the earlier deferred-stub posture: for each chunk-anchored edge (`defined_by` / `exemplifies` only) the aggregator renders the predicate to a hypothesis and runs NLI against the cited chunk text via the shared `lib/classifiers/nli_classifier.py::NliClassifier` DeBERTa singleton (honors `ED4ALL_NLI_DEVICE`, CPU fallback). It emits a single `disagree` signal ONLY on `contradiction >= 0.5` (→ `edge_status: retracted`); entailment / neutral add nothing — the arm can only retract, never confirm. It **requires** a chunk-text lookup threaded from the call site (edges reference chunk IDs, not TEXT; the aggregator otherwise carries only the graph path) — supplied via `load_chunk_text_lookup(course_dir)` / `chunk_text_lookup_from_chunks(chunks)`; when absent the extension no-ops even with the flag on (graceful degrade), as it does when the NLI deps are missing. A per-run `TRAINFORGE_EDGE_NLI_MAX_EDGES` cap (default 500) bounds the NLI forward passes. Recommend one shadow `build()` on the calibration corpus before flipping it on.

  **Contradicted-edge policy** (`TRAINFORGE_CONTRADICTED_EDGE_POLICY`, opt-in, default unset → stamp-only / byte-identical legacy output). By default contradicted edges stay fully in the graph, status-stamped only, so retrieval/pedagogy consumers keep consuming known-bad edges. The policy is the downstream complement to the upstream `TRAINFORGE_PREREQ_LO_ADJACENT_ONLY` prerequisite mitigation (transitive reduction + 0.6→0.3 text-order confidence demotion). Applied **only** on `apply_to_graph` (the mutation path), per-edge after the verdict is computed:
  - `decay` — multiply a contradicted edge's `confidence` by `_DECAY_FACTOR` (0.5) in place; `edge_status` stays `contradicted`. Confidence-ranking consumers down-weight the edge while its contradiction provenance is preserved. Idempotent via the additive `consensus_confidence_predecay` snapshot + `consensus_confidence_decayed` sentinel (a second `apply_to_graph` is byte-identical and cross-edge `consensus_signals[]` keep reporting the original confidence). Composes with the upstream mitigation: an already-demoted 0.3 edge decays to 0.15 (compounding, not conflicting).
  - `retract` — re-status the edge `edge_status: retracted`. The edge is **not** physically deleted (deletion breaks provenance/replay); it stays in `graph['edges']` clearly statused so an `edge_status`-aware consumer can exclude it. In-tree consumers don't filter on `edge_status` today, so the status is the contract; physical removal is out of scope.
  - Any other value raises `ContradictedEdgePolicyError` **before** any edge is mutated (fail-closed — a typo never half-writes the graph or silently degrades to stamp-only).

  **Coherence with the attenuation contract:** `contradiction_rate` is computed in `build()`, which does NOT apply this policy. A decayed or retracted edge still counts toward `contradiction_rate` — it remains evidence of contradiction even after its confidence is decayed or its status re-stamped `retracted`. Attenuating a contradiction is not the same as erasing the signal, so the `(1 - contradiction_rate)` consistency hit stays intact regardless of the policy. `KGQualityValidator.validate` is unchanged.

- `lib/aggregators/block_quality_rollup.py::BlockQualityRollupAggregator` — IB6.6 eight-dimension block→module→course quality rollup. Reads the per-block 0-3 dimension scores from the `block_quality_rubric` GateResult metadata stashed in the `post_rewrite_validation` / `inter_tier_validation` `_gate_results` chain (or accepts scored `Block`s directly for tests), and writes `<libv2_course>/block_quality_rollup_report.json` (schema 1.0; canonical shape pinned at `schemas/aggregators/block_quality_rollup.schema.json`). Falls back to `<project_path>/block_quality_rollup_report.json` when archival hasn't run. Rolls up three tiers using BOTH a mean averaging path AND a per-dimension minimum-floor path: **block** `block_pass = mean(applicable_dims) >= 2.0 AND every core dim (alignment / cognitive_load / accessibility / coherence) >= 2.0`; **module** (week / page group) `module_pass = module_mean >= 2.0 AND every required-dim minimum >= 2.0` (so no weak block hides in a strong average); **course** `course_pass = zero Accessibility-gate failures AND zero Alignment==0 orphan blocks (100% alignment coverage)`. Applies the three hard gates that override the mean: (1) any block scoring Accessibility==0 fails outright + fails the course; (2) assessment Bloom < objective Bloom caps Alignment at 1 (applied upstream in IB6.1, reusing IB3 `alignment_cap_at_1`); (3) interaction-without-feedback caps Feedback + Coherence at 1 (applied upstream in IB6.1 / IB6.2). Carries `summary` (block/module/course pass counts, hard-gate-fail counts, per-dim course minimums, `quality_decision` enum aligned to the `course_status` 5-value enum where it overlaps), `per_module[]`, `per_block[]` (scores + `weakest_dim`). Emits one `block_quality_rollup_aggregated` decision per build (dynamic rationale: block/module counts, hard-gate fails, course minimums). Only runs when `ED4ALL_BLOCK_QUALITY_RUBRIC` is on (default-off → no rollup file, byte-stable). Warning-day-1; the hard-gate critical flip is deferred until the anchored 0-3 scale is calibrated on >=2 corpora.
- `lib/aggregators/concept_coverage.py::ConceptCoverageAggregator` — W4.1 read-only capability aggregator (resolver `resolve_concept_coverage` / `ENV_CONCEPT_COVERAGE`; registered post-loop in `MCP/core/workflow_runner.py::_maybe_write_concept_coverage`). Builds a concept-keyed coverage table — the concept-graph analogue of `coverage_map` — surfacing which pedagogical surfaces (objectives, chunks, blocks, assessments) touch each concept, and writes `<libv2_course>/concept_coverage.json` (schema 1.0; canonical shape `schemas/aggregators/concept_coverage.schema.json`; falls back to the concept-graph dir `<concept_graph>/concept_coverage.json`). Only runs when `ED4ALL_CONCEPT_COVERAGE` is on (default OFF → the aggregator no-ops: no file written, run-return `concept_coverage_path` is None, byte-identical). Best-effort read-only: aggregator failure logs a warning and never changes `final_status` (mirrors `CoverageMapAggregator`). Emits one `concept_coverage_aggregated` decision event per build.
- `lib/aggregators/intelligence_level.py::IntelligenceLevelAggregator` — W4.6 read-only capability aggregator (resolver `resolve_intelligence_rubric` / `ENV_INTELLIGENCE_RUBRIC`; registered post-loop in `MCP/core/workflow_runner.py::_maybe_write_intelligence_level`). Scores a built course on a DETERMINISTIC (no-model) 0-5 capability rubric and writes `<libv2_course>/intelligence_level_report.json` (schema 1.0; canonical shape `schemas/aggregators/intelligence_level.schema.json`; falls back to the trainforge dir `<trainforge_dir>/...`); the `faq` axis is intentionally always-absent (capability not built yet — reserved). Only runs when `ED4ALL_INTELLIGENCE_RUBRIC` is on (default OFF → the aggregator no-ops: no file written, run-return `intelligence_level_report_path` is None, byte-identical). Best-effort read-only: aggregator failure logs a warning and never changes `final_status`. Emits one `intelligence_level_scored` decision event per build.
- `lib/governance/course_status.py::derive_course_status` — Wave 3 W3.G full 5-branch composer. Walks the per-arrow rows produced by `PromotionChainAggregator` and returns the canonical `course_status` enum value via the cohort table: `ACCESSIBILITY_GATE_IDS = {wcag_compliance, wcag_aa_compliance}` (gates `certified_accessible`); `INSTRUCTIONAL_GATE_IDS = {claim_support, content_grounding, oscqr_score, page_objectives, source_refs}` (gates `certified_instructional`); `TRAINABLE_GATE_IDS = {eval_gating, family_completeness, min_edge_count, pair_claim_support, synthesis_diversity}` (gates `certified_trainable`). The two per-claim NLI entailment gates (`claim_support`, `pair_claim_support`, Wave W-D11.B) are warning-severity day-1 and their cohort entries stay dormant until operator calibration flips severity to critical. Anti-silent-degradation: a missing cohort gate disqualifies the cohort (silent crediting an absent gate is the silent-degradation class the helper closes); a hard-fail arrow attached to any critical-cohort gate (or an unattributed `missing_stage_report`) shorts to `failed`. Wave 1 (`compose_course_status`) is preserved for the legacy `failed` / `non_certified_archive`-only branches.
